# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

A fork of [loic-sharma/BaGet](https://github.com/loic-sharma/BaGet), A NuGet, Maven, NVM, Docker and symbol
server. The fork targets `net10.0` and has diverged substantially (accounts, V2 feed, validation,
catalog). Some work here is upstreamed as PRs against `loic-sharma/BaGet`.

## Build and test

**Always pass `-p:GeneratePackageOnBuild=false`.** `src/Directory.Build.props` sets
`GeneratePackageOnBuild=true` with `PackageOutputPath=$(SolutionDir)Packages\`, and `Packages` is a
**symlink to `D:\Starb\Packages`**, a shared NuGet feed. A plain build publishes packages into it, and two `AfterTargets="Pack"` targets
(MSBuild tasks only, so Windows, Linux and macOS alike) then run: `DeleteOldPackage` removes the package's folder (every version, lower-cased id) from the
global packages folder (`$(NuGetPackageRoot)`, else `NUGET_PACKAGES`, else `~/.nuget/packages`), so the next restore takes the fresh package even with an
unchanged version; `DeleteOlderGeneratedPackages` deletes the older `.nupkg`/`.snupkg`/`.symbols.nupkg` of the same id from `$(PackageOutputPath)`, keeping
what this pack wrote (`@(NuGetPackOutput)`; the name must continue with `.<digit>` after the id, so `Extension.BaGet` never touches `Extension.BaGet.Core`).

Three gotchas when running locally:
- It listens on **6060**: `Kestrel:Endpoints:Http:Url` in `appsettings.json` outranks `--urls` and
  `ASPNETCORE_URLS`, so they are silently ineffective (override with `Kestrel__Endpoints__Http__Url`).

- `dotnet run` makes the SDK rewrite `src/BaGet/Properties/launchSettings.json` (it drops the IIS
  Express profile). Revert it rather than committing it.

## Every service has a UI counterpart

Every operation a service, REST endpoint or CLI command offers must also be reachable from the web UI, in the same
change: a feature is not done while it exists only as REST, CLI or a service method. Gate the page like the operation
(same action/permission, antiforgery, password or re-authentication for destructive or access changes,
`MaintenanceGate.ThrowIfClosed` on writes) and link it from the navigation or the page it belongs to. Reviews check it.
Where the UI cannot yet do something the server can (a REST field, a CLI option, a service operation), enrich the UI
to cover it; `docs/ui-coverage.md` maps every capability to its page and gate and must stay complete (`UiCoverageInventoryTests` fails on a controller, controller action (screen) or CLI command with no row there).

## Every docs page is in the solution and reachable

Every Markdown file under `docs/` (recursively) is listed in `BaGet.sln` under the `docs` solution folder (subfolders as
nested solution folders), linked from `docs/index.md` or a page reachable from it, and in the `mkdocs.yml` nav. A new,
moved or deleted page updates all three in the same commit. **Exception: plan documents (`docs/plans/`) are never listed,
linked or put in the nav.**

The SPA samples (`samples/BaGet.Frontend.React`, `samples/BaGet.Frontend.Angular`; not MSBuild projects) are in `BaGet.sln` as linked solution items under `samples/<sample>`, one nested solution folder per subfolder; a new or removed tracked file of a sample updates the solution in the same commit (never `node_modules`, `dist`, `.angular`).

### Subsystems are chosen at runtime, not at registration

Storage, database, search and indexing are each resolved through `IProvider<TService>` chains:
`DependencyInjectionExtensions.GetServiceFromProviders<T>` walks every registered provider and takes
the first non-null, each provider deciding from configuration (`Database:Type`, `Storage:Type`,
`Search:Type`). To add an implementation, register a provider in
`src/BaGet.Core/Extensions/DependencyInjectionExtensions.Providers.cs` and an
`app.AddXyz()` in `HostServiceCollectionExtensions.AddBaGetProviders` (`src/BaGet/Hosting`) — do not resolve concrete types directly.

### Entry point: minimal hosting

`src/BaGet/Program.cs` is the entry point (there is no `Startup`); its building blocks are extension methods in `internal static` classes under
`src/BaGet/Hosting/`. `BuildApplication` runs `AddBaGetSettingsOverrides` / `AddBaGetLogging` / `AddBaGetTelemetry` / `ConfigureBaGetWebHost` /
`AddBaGetHost`, then `UseBaGetPipeline`; `Main` adds the commands with `AddBaGetCommands` (`HostCommandLineExtensions`) and runs
`BootstrapAdministratorsAsync` before the host.
`Main` wraps it in a McMaster `CommandLineApplication` (`import downloads [-r repo]`, `catalog rebuild [-r repo]`, `account reset-password|promote|demote|approve <user>`), which
is configured to **collect unrecognised arguments** so host arguments like `--environment` pass
through.

**Settings overrides file.** `AddBaGetSettingsOverrides` (`HostConfigurationExtensions`) inserts `appsettings.Overrides.json` (path from
`SettingsOverridesPath`, default in the content root / `BAGET_CONFIG_ROOT`) after the last `appsettings*.json`
source and before environment variables and the command line. `SettingsService` /
`SettingsOverridesStore` (`BaGet.Core`) write it; `AddBaGetOptions` records every options type as a
`SettingsSchemaRegistration`, and `[RestartRequired]` / `[SensitiveSetting]` on options classify them.
`[AllowedSettingValues(...)]` (string settings; `Database/Storage/Search:Type`) makes the catalog emit an `Enum`
choice with those values and is also what `ConfigureBaGetOptions` validates against (one list);
`[SettingExample(dependsOn, whenValue, example)]` gives a setting per-value examples (`SettingDescriptor.Examples`),
rendered by `_SettingField` as a placeholder/help line (never the value) via `SettingPresentation`. Examples travel in one `data-examples` JSON attribute (no per-value attribute names); the catalog throws `InvalidOperationException` for duplicate `whenValue`s (case-insensitive) or mixed `dependsOn` on one property. Tests
set `SettingsOverridesPath` to the temp directory; `UseSetting` values arrive through the *last* (chained host)
provider, so they shadow saved overrides — integration tests that save a setting must use keys the harness does
not set.

**Registration-time configuration reads are load-bearing.** `AddBaGetAccounts` decides from
`Accounts:Enabled` *while registering services*, so configuration must be in place before
`BuildApplication` runs. This is why `tests/BaGet.Tests/Support/BaGetApplication.cs` supplies settings
with `builder.UseSetting(...)` and **not** `ConfigureAppConfiguration`, which is merged too late.
Anything read through `IOptions`/`IOptionsSnapshot` is unaffected.

**Host hardening (`Proxy:*`, `DataProtection:KeyPath`; user docs `docs/configuration.md`).** Read from configuration at startup, no Settings page row (`ProxyOptions`/`DataProtectionKeyOptions` are bound in `ConfigureBaGetOptions`/`AddBaGetDataProtection`, not registered with `AddBaGetOptions`, so `ui-forms.txt` is unchanged). `ForwardedHeadersOptions` keeps the framework's loopback-only trust plus `Proxy:TrustedProxies`/`TrustedNetworks`; `Proxy:TrustAnyProxy` clears the lists (the old behaviour, opt-in). A single node persists the key ring with `PersistKeysToFileSystem` in `DataProtection-Keys` beside the overrides file (HA keeps it in the database; the application name is left at its default so existing ciphertexts stay valid). `FormOptions.MultipartBodyLengthLimit` is 1 MiB (`ConfigureBaGetOptions.DefaultFormLimit`); actions that take a file carry `[UploadSizeLimit]` (`BaGet.Api.Base`, a `RequestFormLimitsAttribute`, runs before the antiforgery check): add it to a new upload/push action. `RepositoryResolutionMiddleware` sets `HttpContext.Items[ResolvedItemKey]` and `RepositoryResolutionGuardFilter` (global, first) answers 500 to a `{repo}` route without it (a host that skipped `UseRepositoryResolution`). `Main` returns `Task<int>` (`Program.RunAsync`): 1 for invalid options. The overrides file is inserted after the last `appsettings*.json` (user secrets outrank it). Test harness: `BaGetApplication` puts `Telemetry:Enabled=false` in an in-memory source just below the overrides file (outranked by a `SettingsService` save, invisible on the Settings page), because the shipped `appsettings.json` exports to `localhost:4317`; `HostHardeningTests`, `RepositoryResolutionGuardFilterTests`.

**Read-only gate.** `MaintenanceGate` (`BaGet.Core`, singleton, in memory) closes every database write:
`MaintenanceSaveChangesInterceptor`, added in `AddBaGetDbContextProvider`, throws `MaintenanceException` from
`SaveChanges` while it is closed; `MaintenanceMiddleware` (`BaGet.Web.V3/Middleware`) maps that to 503 + `Retry-After`; the layout
shows a banner. `CloseUntilRestart` cannot be reopened. Code that stores a file and then writes the database must call `MaintenanceGate.ThrowIfClosed` first (`PackageIndexingService`, `ValidatingPackageSubmissionService`, `CatalogWriter`) so a refusal leaves no orphan file. Sign-in must still work (an admin needs the post-copy status): `MaintenanceAwareSignInManager` skips only the lockout-counter reset while closed; a failed attempt is still a refused write. A context built with `MaintenanceGate.AllowWrites(builder)` is
exempt (the copy's target). Code that catches broad `Exception` around a write must not swallow `MaintenanceException`
(controllers, `PackageValidationRunner`); `ValidationWorker` retries after it, `PackageDatabase.AddDownloadAsync` ignores it.
Raw SQL would bypass the gate: there is none outside migrations, keep it so (the one exception, the database copy's
rollback `ExecuteDelete`, runs on the copy's own target context, never on the application's).

**Repositories.** `Repository`/`Project` (`BaGet.Core/Repositories`); `default` (key `Repository.DefaultKey` = 1) is the
repository at `/`. `Package`, `PackageOwner`, `CatalogEntry`, `PackageValidation`, `AbuseReport`, `PackageSymbol` are `IRepositoryScoped`
(`RepositoryKey`, column default 1 = how the `AddRepositories` migration assigns pre-existing rows; a **Restrict foreign key** to `Repositories`, see *Ownership foreign keys*).
The migration (all four providers) also inserts the `default` row with key 1 (PostgreSQL `setval`s the sequence), so
applying migrations outside the app (`dotnet ef database update`, a script) leaves no gap for a new repository to take key 1. `AbstractContext` filters those six on `IRepositoryContext.Current.Key` with global
query filters evaluated per query (the scope is found through EF's `ApplicationServiceProvider`, so a hand-built
context works in `default`) and stamps new rows on save; anything that must see every repository calls
`IgnoreQueryFilters()` (`DatabaseTable` copy/count/delete, `AccountDeletionService`, `PackageValidationRunner` pending list
and submission lookup). A new per-package table must implement `IRepositoryScoped` and get the filter in
`OnModelCreating`. Whoever picks the repository (routing, a worker, a command) calls `IRepositoryContext.Use(info)` before
querying, or uses `IServiceScopeFactory.CreateRepositoryScope(info)`; the validation runner switches to the queued
submission's repository itself. `IRepositoryService` finds/lists/creates (`RepositoryNames` holds the one name rule);
`EnsureDefaultAsync` restores a missing `default` row (explicit key 1) at startup and before `CreateAsync`
(which refuses when rows exist but none has key 1). The copy target is "empty" with only that seeded row, which
`DatabaseCopyService` deletes before copying the source's rows. Azure Table (`NullContext`) and `Search:Type` =
`AzureSearch` (one global index, document keys without a repository) have the default repository only:
`SupportsMultipleRepositories` is false, `CreateAsync` and `TablePackageDatabase` refuse others and
`RepositoryService.FindAsync` serves `default` only (so remote repositories cannot exist there; `Mirror:*` is read directly).
API keys can be limited to repositories (`ApiKeyRepository`; none = all): `AccountAuthenticationService` puts them in `BaGetPrincipal.RepositoryKeys`, `AccessEvaluator` refuses every action outside them (administrators too) and judges a Read as anonymous; `RepositoryAdministration.DeleteAsync` drops the rows and the keys left with none (else they would turn unlimited).
`IRepositoryAdministration` (list with package counts, `SetAnonymousReadAsync`, `DeleteAsync`: refuses `default` and any repository with packages or a pending validation; its
catalog entries, owners, validations and abuse reports are purged with it, and so is `repos/{name}/` in storage when the store is `IListableStorageService`) backs the admin screens `Repositories`, `RepositoryEdit`, `RepositoryDelete` (`AdminRepositoriesController`, `BaGet.Identity/Controllers/FrontEnd`; logic in the `Admin*UseCase`s of `BaGet.Identity.Application/UseCases/Admin`)
(names are immutable; only `AnonymousRead` is editable; writes call `MaintenanceGate.ThrowIfClosed`; feed URLs derive from `IUrlGenerator`).

**Identity table names** (`AbstractContext.OnModelCreating`; migration `RenameAspNetTables` x4): the `AspNet` prefix is dropped (`Users`, `Roles`, `UserRoles`, `UserClaims`, `UserLogins`, `UserTokens`, `RoleClaims`; keys, indexes and foreign keys are renamed with them). Older migrations and the upgrade-test seeds (`PreRepositoryDatabase`, `OwnershipUpgradeDatabase`, `OwnershipOrphanCleanup`) keep the old names on purpose: they run before the rename.

**Ownership foreign keys** (`AbstractContext.BuildOwnershipForeignKeys`; migration `AddOwnershipForeignKeys` x4). `RepositoryKey` -> `Repositories` on every `IRepositoryScoped` table plus `ApiKeyRepositories`, `ReplicationConfigs`, `RetentionPolicies`/`ScanPolicies` (nullable); `ProjectKey` -> `Projects` on `Repositories`, `PermissionTargets`, `RetentionPolicies`, `ScanPolicies` (nullable); `UserId` -> `Users` (formerly `AspNetUsers`, see below) on `ApiKeys`, `GroupMembers`, `OrganizationMembers`; `ReplicationRuns`/`ReplicationItems.ConfigKey` -> `ReplicationConfigs`; `OciTags.ImageKey` -> `OciRepositories`. **No cascade and no navigation property** (public entities unchanged): `Restrict` (`OciTags.ImageKey` is `NoAction`: an image delete cascades to its manifests and from them to the tags, so the check must wait for the end of the statement). Deleting a parent is still done by code, children first: `RepositoryAdministration.DeleteAsync` (+ the format modules' `StagePurgeAsync`, which now also removes Docker images/links/blobs), `AccountDeletionService`, `IAccessAdministration.DeleteProjectAsync` (also the project's retention and scan policies), `ReplicationAdministration.DeleteAsync`, `OciRegistryService.DeleteImageAsync` (tags first). `PermissionGrant`/`ProjectMember.PrincipalId` is polymorphic (user or group): no key. A background write for a deleted parent must skip, not fail: `ArtifactUsageRecorder.FlushAsync` drops the entries of a repository that no longer exists; the scan/replication workers already log and go on. **Upgrade:** the migration first runs `OwnershipOrphanCleanup.Statements` (ANSI `DELETE ... IN (SELECT ...)`, identifiers quoted per engine, children before parents, **before** SQLite rebuilds tables): owned rows of a missing repository are deleted with everything under them; keys/memberships of a missing user are deleted; an API key limited only to missing repositories is **deleted** (dropping its rows would make it unlimited); a policy left with no target is deleted, otherwise the missing reference is set NULL; a permission target of a missing project is **deleted** (nulling would widen it to every repository); a repository of a missing project gets `ProjectKey` NULL. The helper is frozen for that migration. Tests: `OwnershipForeignKeyTests` (model, enforcement, deletions, usage flush, SQLite upgrade), `EngineUpgradeTests.OrphanRowsAreRemoved...` on every engine (`OwnershipUpgradeDatabase`).

**npm registry** (`BaGet.Core/Formats/Npm`, user docs `docs/npm-registry.md`). `INpmRegistry` is `RepositoryNpmRegistry` (scoped), which forwards **per call** by `IRepositoryContext.Current.Kind` to `NpmRegistryService` (local), `RemoteNpmRegistry` or `VirtualNpmRegistry` (resolved per call: a write to a virtual repository continues in its deploy repository inside the same scope); `NpmRegistryService` (scoped, works in `IRepositoryContext.Current`) holds every operation of a local repository: `GetPackument(abbreviated)`, `OpenTarball`,

and goes through `IPackageAuthorizationService` (Push = Deploy for publish and tags, Annotate = deprecate, Manage = Delete after `Npm:UnpublishWindow`; Push is enough inside the window) so routes and pages cannot
differ; results are `NpmResult`/`NpmStatus` (mapped to 400/401/403/404/409 by `NpmController`, `{"error": …}` bodies). Names are `NpmNames` (lower case, `@scope/name`, `%2f` decoded; the one place that validates

(keys and base64 may be JSON-escaped by other encoders) and decodes each attachment from the file to another temp file, so memory is the metadata, never the tarball; `NpmRegistryService.PublishAsync`
hashes it (sha512 SRI + sha1), refuses a declared integrity/shasum/length that differs, reads `package.json` out of the tarball (`NpmTarballReader`, bounded) and requires the same name and version, then stores
the file and writes package/version/tags in one transaction (a unique-index race is a 409; a failure deletes the file it stored). The first version always gets `latest`. `dist.tarball` (rebuilt per request from `IUrlGenerator.GetNpmRegistryUrl`). Routes: `BaGetEndpointBuilder.MapNpmRoutes` registers every package route in two shapes (`{name}` for `@scope%2fname`,
`@{scope}/{pkg}`); `RepositoryReadFilter` decodes the name for the access patterns (`NpmRouteNames`) and adds a `Bearer` challenge; write routes are method-constrained (WritesOnly) and call
`RequestPrincipalResolver.ResolveForWriteAsync` (API key as Basic password / Bearer / `X-NuGet-ApiKey`, **never the cookie session**). Ownership reuses `PackageOwner` (`OwnershipAuthorizationService.ExistsAsync` asks the
repository's format); `npm login` = `INpmTokenService` (`NpmTokenService`, accounts only): password checked like the sign-in page (lockout, confirmed email, no two-factor), token = an API key limited to the repository.
Pages: `NpmPackages`, `NpmPackage`, `NpmUpload` (BaGet.Web), `Packages/NpmManage` (Identity; owners, tags, deprecate, unpublish with password); `NpmInstallSnippets` builds the commands and `.npmrc` lines.

**Docker registry** (`BaGet.Core/Formats/Docker`, user docs `docs/docker-registry.md`; this paragraph is the local registry, remote/virtual/GC follow). OCI Distribution Spec v1.1 **at the server root**, `/v2/{repo}/{image…}/blobs|manifests|tags|referrers/…`: the BaGet repository is the first path segment of the image name (D2), so the routes are *not* under `r/{repo}/`. They are registered once by `BaGetEndpointBuilder.MapOciRoutes` through `MapRoute(..., serverRoot: true)` with `RepositoryRouteMetadata.ResolvesRepositoryItself` (which implies `AuthorizesItself`): neither `RepositoryReadFilter` nor `RepositoryResolutionMiddleware` touches them; `OciAuthorizationFilter` (a `[ServiceFilter]` on `OciController`, every action except `Base`/`Token`) parses the path (`OciNames.Parse`, from the right, the name having any number of slashes), maps method+kind to an action (`OciHttp.Required`: pull = Read, push = Deploy, delete = Delete; a combination it does not define is refused, no default allow), finds the repository (Docker; local, remote or virtual, see below), asks `OciCallerResolver` (a registry token first, else an API key as Basic password/Bearer through `RequestPrincipalResolver.ResolveForWriteAsync`; never the cookie) and only then `IRepositoryContext.Use`. Refusals: anonymous or a token not covering the request = `401` + `Bearer realm=…/v2/token,service,scope` (**also for a repository that does not exist**, so a private repository is not told from a missing one), a key without Read = `404 NAME_UNKNOWN`, with Read but not the action = `403 DENIED`. `GET /v2/token` (`OciController.Token`) grants per requested `repository:{repo}/{image}:pull,push` scope what `IOciAccess` (access model + the key's `package:push`/`pushversion`/`unlist` scope and glob) allows; the token is `IOciTokenService` (`OciTokenService`: ASP.NET Core data protection over a JSON payload of audience, subject name, expiry and the `(repo, image, actions)` grants; **no API key inside**; `Oci:TokenLifetime`; no revocation, a removed permission applies at expiry). `IOciRegistry` (`OciRegistryService`, scoped, works in `IRepositoryContext.Current`) holds every operation and **authorizes nothing** (a token has no principal; callers decide first): upload sessions over `IStreamingStorageService` (`OciUploads` row = reference + storage upload id, bound to its image; idle ones are dropped when a new upload starts), `CommitAsync` verifies the SHA-256 while streaming, blobs stored once per repository at `docker/blobs/sha256/ab/<hex>` and **served only through `OciBlobLinks`** (image to blob; so image-level permissions cannot be bypassed by digest; `OciBlobs.RefCount` = holders, the file goes at 0; `OciBlobLinks.Manifests` counts the manifests using it, raised/lowered by `ExecuteUpdate` `Manifests = Manifests +/- 1` in the push/delete transaction, never written back as a read number, so concurrent pushes cannot lose a reference; Prune, `DeleteBlob` and the GC delete a link only with `Manifests == 0` in the delete's own condition; in-process `OciBlobCommits.LockAsync(path)` serialises an upload's commit+row against a removal's row+file delete; foreign layers (`OciParsedDescriptor.Foreign`) are not required, stored or counted), manifests are `OciManifests` rows holding the JSON exactly as pushed (`OciManifestParser` refuses non-UTF-8/BOM so the digest survives; config, layers and index children must already be linked/present: `MANIFEST_BLOB_UNKNOWN`), tags `OciTags` (case-sensitive: binary collation on SQL Server/MySQL; deleted with their manifest by foreign key), referrers from `OciManifests.SubjectDigest`. Tables migration `AddOciTables` x4; `OciRepositories`/`OciBlobs` are repository-scoped with query filters. `DockerFormatModule` (`RequiresStreamingStorage`, `FeedPath` `v2/{repo}/` = relative to the server root, `RepositoryFeedUrl` handles `{repo}`). Errors are `OciException` (code → status in `OciHttp`); `MaintenanceException` is never caught (503 by the middleware). A read of a reference that is neither tag nor digest is 404 (conformance), only a PUT answers `TAG_INVALID`. Pages: `DockerImages`, `DockerImage` (`?digest=` = manifest detail: config, layers, index platforms) in `BaGet.Web`, `Packages/DockerManage` (delete tag/manifest/image, prune unused layers; Delete action + password) in Identity; the access patterns see the image name as the package id (`RepositoryPageGate` reads the `image` route value); `DockerSnippets`. Options `Oci:*` (`OciOptions`). No upload page (the CLI pushes), no ownership. Tests: Core `OciNamesTests`; `OciRegistryTests` (protocol, token flow, access, deny-by-default route check), `DockerPagesTests` in `BaGet.Tests`; `DockerCliTests` (above).

**Remote and virtual Docker, GC** (docs `docs/docker-registry.md#remote-docker-repositories`). `IOciRegistry` is now `RepositoryOciRegistry` (scoped, forwards per call by `IRepositoryContext.Current.Kind`, like Maven/npm) to `OciRegistryService` (local; `partial`, the cache support is in `OciRegistryService.Cache.cs`), `RemoteOciRegistry` or `VirtualOciRegistry`; `IOciRegistry.ProbeAsync` is the resolution preview. `RemoteProtocol.Docker` (set by `ForFormat`; `RemoteHttpClientFactory` adds **no** credential handler for it: `OciUpstreamClient` authenticates itself). **`OciUpstreamClient`** (scoped, over `IRemoteUpstreamSource`/`RemoteRepositoryState`/`IRemoteHttpClientFactory.CreateProbe`, redirects followed by hand, max 5, never https to http): first request anonymous, `401` + `Bearer realm,service,scope` -> token from the realm (Basic with the credentials, else anonymous; `account=` the user name), kept per scope in `UpstreamTransport.Tokens` (so a changed URL/credential drops them) until `expires_in` minus 10 s; a `Basic` challenge is answered at the registry's origin (`BasicChallenged`); a password with no user name is a static bearer token. The credential goes to the registry origin and the realm only, never to a redirect target (the CDN a layer is redirected to), and a `401` challenge is answered only when it came from the registry's own origin (a redirect target's realm is never asked). `401`/`403` after authenticating = absent (`IsAbsent`, Docker Hub answers a missing or private image so), not a failure; a refused token request is a failure (`InvalidDataException` with a safe message). Cache keys `om:`/`ob:`/`ol:` + `{image}|{detail}` (`MatchesImage` is what a purge drops); an expired tag is revalidated with `HEAD` and `Docker-Content-Digest` against the cached/stored digest. `UpstreamName` puts a single name under `library/` at Docker Hub hosts only. **Blobs** (`RemoteOciRegistry.CacheWhileStreamingAsync`): stream upstream -> client while a `CachingStream` appends to `OciRegistryService.BeginBlobCacheAsync` (an `OciBlobCacheWriter` = a storage upload recorded as an `OciUploads` row so a crash leaves an expirable session, not a lost file), 8 MiB flushes, the **last bytes are held back until the SHA-256 checked and the row recorded** (a client that has all bytes goes on at once; a mismatch reaches it as a failed download), `RecordBlobAsync(countReferences: true)` sets `OciBlobLinks.Manifests` to the number of stored manifests naming the layer (so cached layers are "used" and the GC leaves them); range requests, a digest already being cached (static `Caching` set) and a closed gate pass through; a layer another image of the repository stores is linked once the upstream `HEAD` confirms it (`LinkRepositoryBlobAsync`). Manifests are stored by `StoreCachedManifestAsync` = `PutManifestCoreAsync(checkReferences: false)` (layers/children arrive later). Writes on a remote repository: `OciException(Denied)` = `403 DENIED`; unreachable/unusable upstream with nothing stored = `OciErrorCode.UpstreamUnavailable` = `502 UNAVAILABLE`. **Virtual** (`VirtualOciRegistry`): members from `IVirtualRepositories.EffectiveMembersAsync`, filtered by `IOciRequestAccess.CanPullAsync` (scoped; `OciAuthorizationFilter` sets it to `OciCallerResolver.AllowsAsync(caller, member, …)`, so a **registry token must carry a pull grant per member**: `OciController.Token` adds them for a virtual scope; keys are judged by the access model), each question in its own `CreateRepositoryScope` (the scope of a blob lives as long as `OciBlobContent.Owner`, because a remote member's caching stream still uses its database), first answer wins, tags/referrers/images merged; writes go through `DeployTargetAsync`. `OciAuthorizationFilter` authorizes a push/delete to a virtual repository against the **deploy repository** (`OciRequest.Target`; a token is checked against the virtual name, a key against the target), runs it there (`IRepositoryContext.Use(target)`) while URLs keep the virtual name, and tells a caller who may pull that a remote/deploy-less repository `403 DENIED`. **GC** (`OciGarbageCollector`, `IOciGarbageCollector`, scoped, one repository of `IRepositoryContext`): expired `OciUploads` sessions; links with `Manifests == 0` older than `Oci:PruneGrace` except images with a non-expired session; blobs with no link left (and unlinked rows older than the grace period); files under `docker/blobs` no row names (`IListableStorageService`; skipped when `OciBlobCommits` shows a commit running or started during the listing, a process-wide counter around "file stored, row not yet written", and the rows are re-read after the listing; other nodes are not fenced); a dry run computes the same plan and changes nothing. Started from the Operations page by `OciGarbageCollectionDryRunOperation`/`OciGarbageCollectionRunOperation` (`IAdminOperation.AppliesTo(repository)` limits the rows to local/remote Docker repositories; `RequiresConfirmation` makes the page ask the password for the run); the schedule is a retention policy with `CollectGarbage` (see *Retention*). Tests: Core `OciUpstreamTests`; `FakeOciUpstream` (in-memory registry with the token flow, CDN redirect, private images, ranges, corrupt blobs, lying digests), `RemoteOciRepositoryTests`, `VirtualOciRepositoryTests`, `OciGarbageCollectorTests`, `AdminDockerRemoteVirtualTests` in `BaGet.Tests`; `DockerRemoteVirtualCliTests` in `BaGet.Clients.Tests` (real Docker pulling through a remote repository whose upstream is a private second BaGet, a public one and the reference `registry:2`, and through a virtual repository; `docker builder prune`/`image prune` between steps, else the daemon skips layers it still has).

**Streaming storage** (`IStreamingStorageService : IStorageService`, `BaGet.Core/Storage`; user docs `docs/formats.md#streaming-storage-b2`). Optional
capability for blobs too big to buffer (Docker layers): `BeginUpload` / `Append(id, offset, chunk)` (wrong offset =
`StorageUploadOffsetException` with the real length) / `Commit(id, path, sha256?)` (path only known at commit) / `Abort`, plus `GetInfo`

(resumable session over HTTP + tail) and Aliyun (as S3; **no emulator**, unverified live). S3/Aliyun/GCS read a range as 64 MiB windows (`WindowedReadStream`, retries from the exact byte); Azure orders staged blocks by the index inside the base64 id, never by id text. Uploads live under `.uploads/`; a node that
lost the running SHA-256 (`UploadDigestTracker`) recomputes it streaming at commit. `IFormatModule.RequiresStreamingStorage` makes
`RepositoryService.CreateAsync` refuse (`StreamingStorage.Require`) a non-virtual repository of that format on a store that cannot stream.
`tests/BaGet.Storage.Tests`: one contract (`StreamingStorageContract`) per provider on Testcontainers (Azurite, S3Mock, `oittaa/gcp-storage-emulator`),
skips without Docker; `BAGET_STORAGE_LARGE_BYTES=5368709120` runs the 5 GB memory test (run one provider at a time: the probe is process-wide).
Kestrel's body limit is off (`Program.cs`); IIS caps a single request (`IISServerOptions.MaxRequestBodySize`, `maxAllowedContentLength`), so chunk or raise them.

A stamp change caused by the current token session (`MaintenanceAwareSignInManager.RefreshSignInAsync`, which keeps a cookie session signed in) answers renewed tokens in the `X-Session-*` headers (`SessionHeaders`, exposed to CORS). Only `/api/ui` accepts a token: `RequestPrincipalResolver` treats a `bgs.` credential elsewhere as no credential (tested on push, `/api/v1`, the registry). Settings `Accounts:SessionTokenLifetime` (15 min) / `Accounts:SessionRefreshLifetime` (14 days) are `[HiddenSetting]` (the Settings page, and so `ui-forms.txt`, stay unchanged). Tests: `UiApiSessionTests`, `UiApiHostingTests`. **Hosting a single-page application** (`src/BaGet/Hosting/HostFrontendExtensions.cs`, `docs/configuration.md#single-page-applications`): `Cors:AllowedOrigins` (`CorsSettings`, `ConfigureBaGetOptions.AllowedOrigins`, validated in `AddBaGetHost`: an invalid entry stops startup; three policies, `AllowAll` for everything but `/api/ui`, `UiApi` and `UiApiSession`: with a list the listed origins with credentials on `/api/ui` only, with no list any origin without credentials except `session*`/`antiforgery`/`account/*`, which allow none), `Frontend:SpaPath`/`Frontend:SpaBasePath` (`FrontendOptions`: static files under the base path before routing, `MapFallbackToFile(…/{*path:nonfile})` last so nothing is shadowed; root, a fixed list and the first segment of every mapped route refused at startup), `Frontend:SpaLinks` / `!Mvc` with `SpaPath` / `Frontend:SpaUrl` for an application hosted elsewhere (absolute links; `EmailLinksWouldBeDead` stops startup when mail is configured and nothing is linkable; `FrontendOptions.EmailLinkBase`: `SiteOptions.SpaLinkBase`, hidden, set by `AddBaGetAccounts`, makes `AccountLinks`/`AccountSupport.AbsoluteLink` build `{SpaBasePath}/confirm-email|reset-password|sign-in` links and the cookie login path), `Frontend:Mvc=false` (the host does not call `AddBaGetFrontEnd` and `RemoveBaGetFrontEnd` strips the screens' application parts, which the Razor SDK registers on its own for assemblies the host references). A new screen = a use case + DTOs in the Application project, a twin, a view controller that invokes and renders. **Every twin is in the OpenAPI `ui` document** (`ApiControllerBase` carries `[ApiExplorerSettings(IgnoreApi = false)]`, since twins are not `[ApiController]`; `OpenApiDocumentTests` checks each route and method, plain and `r/{repo}`). OpenAPI/Scalar: `docs/scalar.md`.

**MVC application parts are registered by BaGet, not the host.** `AddBaGetApplicationParts`
(`src/BaGet.Web.V3/Extensions/IServiceCollectionExtensions.cs`) adds every API assembly with controllers; `AddBaGetFrontEnd()` (`BaGet.Web.FrontEnd`, namespace `BaGet`, called by the host after `AddBaGetWebApplication`) adds the front ends (`BaGet.Frontend.Base` for the layout, `BaGet.Identity.FrontEnd`, `BaGet.Web.FrontEnd`), Razor Pages, `RepositoryUrlHelperFactory` and `UiActionMap`; a host without the Web SDK has no generated `[ApplicationPart]` attributes. A new such assembly must be added to one of them. A host that does not call `AddBaGetFrontEnd()` serves the APIs only. The UI static files are `src/BaGet/wwwroot`, served by the host also at `/_content/BaGet.Web` (`UseBaGetPipeline`), the URL the layout links.

Routes are named constants in `src/BaGet.Web.V3/Routing/Routes.cs`, mapped in `BaGetEndpointBuilder.MapEndpoints` (via `MapRoute`, see *Repository routes*),
and absolute URLs are built only via `IUrlGenerator` — add a member there rather than assembling URLs
in a page or controller.

### Second databases: `IDatabaseContextFactory`

Each relational provider registers an `IDatabaseContextFactory` (`BaGet.Core`; `Add{Sqlite,SqlServer,PostgreSql,MySql}Database`,
none for AzureTable) that opens an `IContext` on an *arbitrary* connection string, configured through the same
`Configure` method as the application's own context (`Database:MySqlServerVersion` honoured, else `AutoDetect`
against the target). Resolve `IEnumerable<IDatabaseContextFactory>` and match `DatabaseType`; `Create(..., configure)`
takes an `Action<DbContextOptionsBuilder>` hook. The caller owns and disposes the context.

`IContext.BeginKeyedInsertAsync` / `EndKeyedInsertAsync(IEntityType)` bracket inserts with explicit generated keys:
SQL Server runs `SET IDENTITY_INSERT` and keeps the connection open between the calls (the setting is per session);
PostgreSQL `setval`s the serial/identity sequence past the max key in `End`; SQLite and MySQL need nothing (explicit
keys advance their counters).

### Database copy (`DatabaseCopyService`, `BaGet.Core/Entities/Copy`)

The Settings page's "Copy all data" option queues a `DatabaseCopyRequest` (`TryQueue` closes the gate and refuses a
second copy); `DatabaseCopyWorker` (single-slot channel) runs it; progress is in memory (`Status`), polled via
`?handler=CopyStatus` (admin only). `DatabaseTable.InDependencyOrder` topologically sorts `Model.GetEntityTypes()` by
foreign keys (Identity's tables included), so a new table is covered with no list to keep. Rows are read in batches of
1000 ordered by primary key; they are loaded **tracked** only to capture **shadow properties** (the FK of a package's
types/frameworks/dependencies is shadow) into `CopyRow.Shadow`, then the tracker is cleared. Pre-flight
(`DatabaseCopyPreflight`, given the target's **design-time** model for column types/collations) runs before the target is created or
migrated and reports, only where the target engine enforces it: over-length strings (SQL Server/PostgreSQL/MySQL), case-only
duplicates in unique indexes and keys (columns `NOCASE`/`citext`/`*_ci`, else the engine default: SQL Server, MySQL) and local dates
(PostgreSQL); a non-empty target needing migration is refused with "schema was updated"; `Unspecified` dates are stored as UTC. Verification uses an order-independent key checksum (`DatabaseTable.Checksum`; engines collate differently). Once settings saving starts, a failure keeps the target and closes the gate until restart (`FailAfterSaveAsync`). A cancellation inside `SettingsService.SaveAsync` happens before the file rename, so it rolls back. Test seams
`DatabaseCopyService.AfterBatch` / `BeforeSettingsSaved` / `AfterSettingsSaved` inject failures. Errors are scrubbed of the connection string
(`DatabaseCopyService.Scrub`); never log it.

### Logging

The host (and only the host) uses Serilog: `AddBaGetLogging` (`HostLoggingExtensions`) clears the Microsoft providers and calls
`AddSerilog(... ReadFrom.Configuration ... , writeToProviders: true)`, so the `Serilog` section of `appsettings.json`
is the one source of truth for levels and sinks (`SerilogOptions` lists `MinimumLevel:Default` and `EventLog:*` on the Settings page; `MinimumLevel:Override` levels have their own *Log levels per source* panel there (`SettingsService.GetLogLevelOverrides`/`SetLogLevelOverrideAsync`, rules in `LogLevelOverrides`: remove only what the overrides file holds); sinks stay file/env only) (Console, File `logs/baget-.log`, resolved against the content
root / `BAGET_CONFIG_ROOT` for every File sink by `ResolveLogFilePaths`). `ApplyDefaultMinimumLevels` sets a code floor
before `ReadFrom` (Microsoft and `Hosting.Diagnostics` Warning: that logger prints `?apikey=`), so a host with its own
appsettings is safe. A sink with `Enabled=false` is blanked (`DisableSinks`; an empty env var is deleted on Windows).
On Windows a Serilog EventLog sink (Warning+, source `.NET Runtime`, `Serilog:EventLog:Enabled`) replaces the Microsoft
provider that `ClearProviders` removes. SelfLog goes to stderr. MinimumLevel reloads live, sinks need a restart. Libraries keep `Microsoft.Extensions.Logging.ILogger`. There is
**no static/bootstrap logger** (it would throw "already frozen" when `WebApplicationFactory` builds a second host).
`app.UseSerilogRequestLogging()` sits after forwarded headers/path base; its template has the path only, never the
query or headers (API keys); a credential inside a path (npm logout's `-/user/token/{token}`) is masked by `RequestPathRedaction` in the log (`GetMessageTemplateProperties`) and, through `RequestPathRedactingEnricher` (after `FromLogContext`, every string property of every event: the hosting scope's raw `RequestPath` rides on each event logged in a request; `LogScopeRedactionTests`), and in traces (`PathRedactingProcessor`, `url.path`/`url.full`). `writeToProviders` delivers each event twice to a registered `ILoggerProvider`;
tests that count lines use `Distinct()`. The harness switches the sinks off with `Enabled=false`.
`WebApplicationFactory` `UseSetting` gives every parent key of a setting an empty value, which Serilog reads as a sink
name, so a test that needs a working File sink runs `Program.BuildApplication` with command-line args instead.

### Telemetry

Libraries emit through `BaGetDiagnostics` (`BaGet.Core/Telemetry`): `Source` (`ActivitySource`) and `Meter`, both named
`BaGet`, plain `System.Diagnostics` (no OpenTelemetry package outside the host). `StartActivity` returns null without a
listener, so spans cost nothing. Spans: `package.index` (`PackageIndexingService`), `package.validate`
(`PackageValidationRunner`), `mirror.fetch` (`PackageService`, `RemoteNpmRegistry`), `database.copy` + `database.copy.table`
(`DatabaseCopyService`); counters `baget.packages.pushed`, `baget.downloads`, `baget.validation.results`. Tags are
`BaGetDiagnostics.Tags` (id, version, result, table, counts); never keys, connection strings or user data, and a failure
records the exception type only (`Fail`). `TelemetryOptions` (`Telemetry:*`, live except `ServiceName` and `Metrics:ExportInterval`, which are `[RestartRequired]`) validates itself
(`Validate()`, called from `ConfigureBaGetOptions`). Tests listen with `DiagnosticsCapture` (linked into `BaGet.Tests`);
the sources are process-wide, so tests that count measurements join its `Diagnostics` collection (runs alone).

**Export (host only, `src/BaGet/Telemetry`).** `AddBaGetTelemetry` (called from `BuildApplication` next to `AddBaGetLogging`)
always builds the providers; whether anything is exported is decided live from `IOptionsMonitor<TelemetryOptions>`
(`AddBaGetOptions` has no change token, so it registers a `ConfigurationChangeTokenSource` for `Telemetry`):
`DynamicSampler` drops everything unless `Enabled` and a traces endpoint are set, then `ParentBased(TraceIdRatio)`;
`ReloadableTraceExporter` / `ReloadableMetricExporter` (`ReloadableExporter<T>`) and `ReloadableOpenTelemetrySink` hold the
real OTLP exporter in a `SwappableHolder<T>` (lease counted: a swap never waits for or cuts an export, the old exporter is
disposed once after its last lease, `ForceFlush` / `Shutdown` reach the current one) and rebuild only when
`TelemetryEndpoints.Key` changes (endpoint, protocol, headers, timeout, level), since every configuration reload fires
`OnChange`. Off = no inner exporter, no connection. Logs are a Serilog sink (added in `AddBaGetLogging`), **not** an
`ILoggerProvider` (`writeToProviders` would export each event twice); it carries `TraceId`/`SpanId`, applies
`Logs:MinimumLevel`, ignores `Grpc.Net.Client` / `System.Net.Http` events (feedback loop) and sees only what the Serilog
levels let through. Traces use `Otlp:Endpoint`; metrics and logs only their own endpoint (Jaeger takes traces only); with
`HttpProtobuf` `/v1/<signal>` is appended. Queue bounded (2048, `TelemetryServiceCollectionExtensions.MaxTraceQueueSize`).
`TelemetryStatus` (per signal: last attempt/success, failing since, scrubbed error) is fed by the exporters
(`ExportStatusHandler` for logs); every message goes through `TelemetryStatus.Scrub` (URLs cut to host, header values
replaced). `TelemetryConnectionTester` exports one synthetic span with explicit settings. The Settings page (BaGet.Identity cannot reference the host) reaches both through `ITelemetryDiagnostics` (`BaGet.Core`, implemented by the host's `TelemetryDiagnostics`; null args = saved values): the Telemetry section's status table, and `SettingsModel.OnPostTestTelemetryAsync` (admin, antiforgery, password-confirmed, posted unsaved `v:Telemetry:Otlp:*` fields, blank sensitive Headers = saved, nothing saved; `TelemetrySettingsPageTests`). **Privacy:** the ASP.NET Core
instrumentation redacts `url.query` values and records no headers, `SqlTextRedactingProcessor` strips the SQL text the EF instrumentation always records (`db.query.text`/`db.statement`/`db.query.summary`, renaming a span named from them; `SqlTextRedactingProcessorTests`, `TelemetryExportTests.DatabaseSpansNeverCarrySqlText`); the log sink uses the startup `ServiceName` (not part of the rebuild key), `ReloadableOpenTelemetrySink.Dispose` waits for sinks still leased by an `Emit`; a host without `ITelemetryDiagnostics` (embedded) gets a "no effect here" note on the Settings Telemetry section; logs are exported as written, audit lines with user names included (documented); never add an `Enrich` copying
either (`TelemetryExportTests.NeitherQueryValuesNorHeadersReach...`). **SDK quirks:** `BaseExporter.ParentProvider` (the
resource) has an internal setter, so `ReloadableExporter.Adopt` sets it by reflection on the inner exporter, and the batch
processor's `DroppedCount` is read by reflection; both degrade (empty resource, 0) if the SDK changes. Versions are levers in
`src/Directory.Build.props` (`OpenTelemetryPackageVersion` 1.20.0 needs Options/Configuration 10.0.0, which restores cleanly
beside the EF 10 / Extensions 10.0.13 pins; 1.13.x would avoid that but has known
vulnerabilities; `OpenTelemetry.Instrumentation.EntityFrameworkCore` exists only as prerelease, `1.20.0-beta.1`, and is
behind the live `Traces:Database`). Tests: `InMemoryTelemetry` (replaces `ITelemetryExporterFactory` through the harness's
`configureServices`; telemetry is off in the harness unless a test enables it, saving through `SettingsService` so the
reload path is the Settings page's), `FakeOtlpCollector` (real exporters over HTTP, no Docker), `ReloadableExporterTests`.

## Code layout (BaGet.Api.Base, BaGet.Catalog, BaGet.Frontend.Base, BaGet.Identity.Api, BaGet.Identity.Application, BaGet.Identity.FrontEnd, BaGet.Validation, BaGet.Web.Application, BaGet.Web.FrontEnd, BaGet.Web.V3)

One type per file named like it, no nested types, namespace = the project's `RootNamespace` + folder (folders name the functionality: `Models/<area>`, `UseCases/<area>`, `Services/<area>`, `Routing`, `Filters`, `Middleware`...), and every controller in the folder of its kind: `Controllers/FrontEnd` screens (controllers returning a view), `Controllers/UI` `/api/ui` twins (`<Screen>ApiController`, deriving the `ApiControllerBase` family), `Controllers/Base` bases, `Controllers/Api` `/api/v1` (deriving `AdminApiController`/`AccessApiController`; `CodeLayoutTests` tells the two apart by base type), `Controllers/Protocols` package protocols. `CodeLayoutTests` enforces it; the only namespace exceptions are `BaGetEndpointBuilder`, `IServiceCollectionExtensions` and `FrontEndServiceCollectionExtensions` (namespace `BaGet`, for discoverability). `Controllers/FrontEnd` exists only in the two FrontEnd projects.

## Strong naming

Every project of `BaGet.sln` (src, tests, samples) is signed with `SignKey.snk` at the repository root. The root
`Directory.Build.props` sets `SignAssembly`, `AssemblyOriginatorKeyFile` and `BaGetPublicKey` (the full public key);
`src/` and `tests/Directory.Build.props` import it (MSBuild reads only the nearest props file), samples read it directly.
Public key token `a5ab967c088e8330`. Every `<InternalsVisibleTo>` in a project file needs `Key="$(BaGetPublicKey)"`
(an unsigned friend name is CS1726). The key file is in the repository (so are git worktrees); a checkout without
`SignKey.snk` at its root cannot build. Moq on `internal` types would need `DynamicProxyGenAssembly2` with Castle's
well-known key; none is used today. The only unsigned dependency is Markdig (no CS8002 is raised; .NET loads it).

## Packaging

Every packable project's `README.md` is its package readme (`PackageReadmeFile`, set in `src/Directory.Build.props`
when the file exists). It renders on nuget.org, so links must be absolute.

`Extension.BaGet` (the `BaGet` host) also packs `BaGet.Web/wwwroot` at `wwwroot/` (a `None` item in

## Package versions

All shared versions are single levers in `src/Directory.Build.props`; provider projects must read them
rather than pinning literals (divergence there once resolved an EF 8 request to EF 10).

**Entity Framework is 10.0.13** (`MicrosoftEntityFrameworkCorePackageVersion`, Identity's stores, `Microsoft.Extensions.*`,
Npgsql 10.0.3). MySQL uses `Microting.EntityFrameworkCore.MySql` 10.0.13 (a maintained fork of Pomelo, which stalled at EF 9; same
API, namespaces `Microting.EntityFrameworkCore.MySql.*`, provider name `Microting.EntityFrameworkCore.MySql`); it constrains
`Microsoft.EntityFrameworkCore.Relational` to `[10.0.13, 10.0.999]`, so all four providers move together and EF must not be
raised past that range until Microting releases. `Microsoft.Extensions.*` tracks EF because holding it lower is an `NU1605`
downgrade error. `BaGet.Database.SqlServer` pins `System.Security.Cryptography.Pkcs` 10.0.13 (SqlClient's 9.0.11 is NU1902/NU1903).

## Migrations

Each `BaGet.Database.*` project has an `IDesignTimeDbContextFactory` using a hardcoded connection
string and `ServerVersion.Parse` (never `AutoDetect`, which opens a live connection). A schema change
needs a migration **per provider**, and all four must report no pending model changes.

- Verify a provider without a server: `dotnet ef migrations list --context <X>Context` in its folder.
- **`dotnet ef migrations remove --no-build` has deleted the wrong (previous) migration** on PostgreSQL
  and MySQL because of a stale assembly; without `--no-build` it needs a live database. Delete the
  generated files by hand and restore the snapshot from `HEAD` instead.
- A migration that adds a foreign key to existing data deletes/detaches the orphan rows first (`OwnershipOrphanCleanup`, see *Ownership foreign keys*); on SQLite put that SQL **before** the operations that rebuild the table.
- Model-level cascade-delete configuration caused `PendingModelChangesWarning` across every integration
  test; orphan cleanup lives in `PackageDatabase.HardDeletePackageAsync` instead.

Documentation is mkdocs (`mkdocs.yml`, `docs/`; `docs/plans/` excluded). `.github/workflows/docs.yml` builds it with `--strict` and deploys it to GitHub Pages (https://pieroviano.github.io/BaGet/) on every push to `main` (Pages source must be "GitHub Actions").
